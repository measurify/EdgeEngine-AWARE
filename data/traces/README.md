# Traces

Hourly weather and soil series that `edgeengine_aware.traces` replays through the simulator
instead of its stochastic models (see `examples/trace_driven.ipynb` and README §10).

| file | what it is |
|---|---|
| `demo_liguria_2023_hourly.csv` | **Synthetic** stand-in, generated by `tools/make_demo_trace.py` (seed 2023): astronomical clear-sky irradiance for 44.05 N / 8.21 E with persistent cloudiness, Markov wet/dry days with gamma rainfall (~870 mm/year), a top-soil water bucket with drainage, evapotranspiration and summer irrigation, seasonal/diurnal temperature. It is **not measured data**; it exists so that the code, the tests and the notebook run without network access. |
| `albenga_2023_hourly.csv` | *(not shipped)* the real ERA5 / ERA5-Land reanalysis for Albenga (Liguria): create it with `python tools/fetch_open_meteo.py` (defaults: this site, year 2023). Source: Open-Meteo historical weather API, licence CC BY 4.0. The notebook uses it automatically when it exists. |

*Reanalysis* data (ERA5, ERA5-Land) is a physically consistent reconstruction of past weather
on a grid, produced by assimilating observations into a weather model; it is the standard
free source of hourly irradiance, temperature, precipitation and modelled soil moisture for
any location.

## File format

```
# site=Albenga, Liguria, IT           provenance, as "# key=value" lines
# utc_offset_h=1.0                    timestamps are local *standard* time: a fixed offset from UTC,
# start_local=2023-01-01T00:00        no daylight-saving jumps, so every day has exactly 24 rows
# unit:shortwave_radiation=W/m²       (informational)
# kind:shortwave_radiation=preceding_mean
# kind:precipitation=preceding_mean
time,shortwave_radiation,soil_moisture_0_to_7cm,temperature_2m,relative_humidity_2m,precipitation
2023-01-01T00:00,0,0.3129,4.19,73.3,0
2023-01-01T01:00,0,0.3128,3.95,74.9,0
```

* `time`: an ISO-8601 local timestamp, or a plain number of seconds. The loader re-bases it
  to seconds since the first local midnight, so the simulator's time of day matches the
  trace's sun.
* `kind` of a column (also settable with `Trace.from_csv(..., kinds={...})`):
  * `preceding_mean` — the value stamped *t* is the mean (irradiance, W/m²) or the sum
    (precipitation, mm) over the hour that **ends** at *t*. This is how weather archives
    deliver these variables. The loader treats the value as constant over that hour.
  * `instant` — the value is the state at *t* (soil moisture, temperature, humidity); the
    loader interpolates linearly between samples. Columns with unknown names default to it.
* Units: irradiance in W/m² (`TraceSolarEnergySource` divides by 1000 W/m² and multiplies by
  the panel's peak power and converter efficiency); soil moisture volumetric, in m³ of water
  per m³ of soil (`TraceFieldEnvironment` divides it by the *field capacity*, 0.40 by default,
  to obtain the simulator's "fraction of field capacity"); temperature in °C; relative
  humidity in % (values above 1.5 are taken as percent and divided by 100); precipitation in
  mm.
* Gaps (empty cells) are filled by interpolation.

## Using your own data

Any CSV with the columns above works. Different column names or a different sampling
interval are fine — pass the names to the backends and let the loader interpolate:

```python
import edgeengine_aware as ea
from edgeengine_aware.traces import Trace, TraceDrivenEnv

cfg = ea.default_config()
trace = Trace.from_csv("my_field.csv", kinds={"ghi": "preceding_mean"})
env = TraceDrivenEnv(
    trace, cfg,
    field_capacity=0.35,
    source_kwargs={"column": "ghi"},
    field_kwargs={"moisture_column": "vwc_10cm", "temperature_column": "t_air", "humidity_column": None, "precipitation_column": None},
)
```

`TraceDrivenEnv(trace, cfg, start_day=k)` replays a fixed window; `start_day=None` (default)
draws a random admissible day at every `reset()`; `reset(options={"start_day": k})` overrides
it for one episode; `harvesting=False` or `field=False` keeps the simulated model for that
part. The trace must cover the episode length plus one day. `info["trace_start_day"]` and
`info["trace_day"]` report where in the trace the episode is.
